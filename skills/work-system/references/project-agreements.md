# Project agreements

Read the project record identified by the navigator and the relevant release plan linked from
this effort's accepted sources. Use their agreed requirements throughout the work and include
the relevant sources in delegated assignments. Read relevant setup and operating instructions
linked from the project record.

When planning a project or preparing implementation tickets, create `docs/project.md` if it is
missing. Link existing detailed sources instead of repeating their agreements. Save agreed
decisions and open questions before replying.

Discuss new or changed project commitments with me before making them requirements or tickets.
Technical capability and available test machines do not decide which platforms we support.
Apply existing agreements and delegated judgment without asking for repeated approval.

A release plan is optional. Work can proceed before release timing, versioning or other release
choices are settled when those choices do not affect its requirements. Finishing an effort does
not establish release readiness or permission to publish.
