# Project planning

Establish or revise decisions that apply across a project, or plan a release. Use this within
planning and return to the effort's discussion afterward.

## Establish the agreements

Use `scripts/navigate.py project` to locate `docs/project.md`.

Read existing specifications, decisions, documentation and relevant implementation. Distinguish
accepted commitments from proposals, observed capabilities and unknowns. Link existing detailed
documentation from `docs/project.md`. Discuss conflicting sources rather than choosing
whichever permits the work to continue.

Discuss the choices needed for the requested work: its purpose and intended users, support
commitments, shared constraints, and release or versioning decisions when relevant. Explain the
practical consequences and recommend an answer when the facts support one. Keep other choices
open without making them blockers for unrelated work.

Record agreed conclusions and their reasons in the project document. Keep questions and
recommendations visibly separate from agreement. Link detailed feature requirements, technical
decisions and supporting evidence instead of copying them. Use the displayed `project-records`
format.

## Plan a release when needed

Use an existing relevant release plan or a document under `docs/releases/`. A descriptive name
can precede a chosen version. Record its audience, included work, supported environments,
required checks, and version and timing when agreed. Keep unanswered choices explicit.

Record versioning policy once in the project document and link it from releases. Apply an
existing policy within the judgment already delegated. An existing version string does not
itself establish a future release, numbering policy or compatibility promise.

## Carry changes into the work

After agreement, update the shared decision and affected specifications, tickets, dependencies
and acceptance checks together. Link the project record and relevant release plan from the
effort's accepted sources. Keep completed work and evidence that remain valid. Remove duplicate
current requirements by linking their shared source; preserve useful reasons and history.

Use the selected tracker's existing document review and publication rules. A draft
or published file does not by itself establish my agreement.

## Result

Record the agreed decisions, remaining questions, affected work and source links. Return to the
current effort with only its genuinely unresolved decisions blocking it.
