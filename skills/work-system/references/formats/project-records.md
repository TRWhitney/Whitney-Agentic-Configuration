# Project and release records

Use these subjects as needed; omit empty sections.
Keep current agreements and unresolved questions distinct. Link details that already have a home.

## Project document

Location: `docs/project.md`.

- Purpose and intended users.
- Agreed support commitments and constraints that apply across features.
- Versioning policy and compatibility promises, when agreed.
- Open project questions and proposals.
- Links to relevant efforts, release plans, specifications and technical decisions.
- Project rule tables or links to them, when maintained.

Record each agreement once, with its reason or decision source when needed to understand it.
Feature specifications describe the feature and link applicable shared agreements.

## Release plan

Default location: `docs/releases/<release-name>.md`, created when a release is being planned.

- Intended audience and included work, linked to its specifications or tickets.
- Supported platforms and environments for this release.
- Agreed readiness checks and links to their evidence or remaining gaps.
- Version and timing, when chosen, with a link to the project's versioning policy.
- Open release questions and links to decisions changing earlier plans.

An open date, version or release choice remains open until needed. Do not create placeholder
release plans merely to complete a project's records or finish unrelated work.
