# Main procedure paths and planning judgment

Five new tasks bring the corpus to 151 cases. They reuse the existing runtime, private checks,
browser tools and blinded assessment. Subject skills and configuration are unchanged.

## Coverage

| Case | Existing coverage | Added condition |
| --- | --- | --- |
| `new-interface-design` | Restoration of an accepted design and prototype revision | Design an equipment handover screen without an accepted visual direction. Plan before building, ground hierarchy in the task, operate and inspect alternatives, and leave selection open. |
| `tracker-converts-existing-work` | Tracker selection, publication and service failures | Convert a complete local effort, preserving accepted requirements, ticket status, research, runnable prototype and links. Verify destinations before removing sources and recover an ambiguous creation result. |
| `worker-completes-valid-assignment` | Missing or invalid worker inputs and parent integration | Complete a valid supplied assignment: observe its real assertion failure, repair production code, pass focused and affected checks, and return an accurate handoff within permitted paths. |
| `complete-research-investigation` | Individual unreliable claims and incomplete experiments | Investigate a storage choice across requirements, original sources, executable comparisons, independent checks, limits and one existing report. Keep product preferences open. |
| `wayfinding-derives-settled-choices` | Progress, recovery and decision records | Derive availability consequences from accepted capacity rules and facts. Use judgment for routine internals and ask about the unresolved staff experience. |

## Grader checks

Worker controls accept two correct implementations and reject six plausible defects. They
also reject missing, misordered, unsuccessful or unrelated red/green evidence. Research probes
reproduce interrupted paired saves, stale edits across windows and offline reopening. Their
checks permit report alternatives while protecting source material. Executable equipment facts
support the planning expectations.

The local GitHub service supports repository access and native parent/child links. Regression
checks cover relationship persistence, duplicate rejection and help without mutation or consuming
the pending timeout. URL targeting, creation responses, labels and rejection of unsupported
commands have controls. Command behavior follows the [GitHub CLI manual](https://cli.github.com/manual/gh_issue_create)
and [label options](https://cli.github.com/manual/gh_issue_edit). No real GitHub service is used.

All eight assessments completed, including three excluded conversion attempts. No time or token
guard was reached.
