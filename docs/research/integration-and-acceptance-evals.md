# Integration and acceptance

Three new tasks and one conversation extension bring the corpus to 146 cases. They reuse the
existing fixtures, private checks, browser tools and blinded assessment. Subject skills and
configuration are unchanged.

## Coverage

| Case | Existing coverage | Added condition |
| --- | --- | --- |
| `delegated-parts-fail-together` | Incomplete returned worker code | Both returned components pass their own checks, but their connection passes raw text to an integer interface. The parent must deliver a working public command. |
| `experiment-measures-partial-operation` | Source reliability and unresolved research | A reported fast measurement excludes data loading required by the accepted time limit. Inspect what was measured and answer from complete evidence. A source-derived lower bound is valid. |
| `contractual-service-interaction` | Rejecting incidental internal-call assertions | An external service requires an ordered exchange. Tests may replace that service while executing real application logic; different valid substitutes are allowed. |
| `interactive-prototype-comparison` | Repair, comparison and unconfirmed preference | Continue through production selection, interpretation and confirmation, retaining required behavior and layout separately from flexible sample items and colors. |

## Grader checks

Both worker checks pass while the command contract fails. A connecting conversion repairs the
command; an incorrect constant quantity fails. The service check accepts two CSV encoders and
rejects missing payloads, forged receipts and wrong upload tickets. It uses no external service.
The timing control establishes that rendering excludes the modeled wait while the complete
operation includes it, without relying on a timing threshold in framework tests.

The prototype keeps its existing repair and browser checks. Later requests select the dialog
and confirm production requirements without instructing the candidate how to record them.
Earlier failure history and worker handoffs are supplied context, not observed worker actions.

## Outcomes

Candidates and separate blinded judges used `gpt-6.1-sol`. The four valid attempts have
**three correct behaviors and one incorrect behavior**. All five assessments completed,
including the excluded earlier prototype attempt. No time or token guard was reached.

| Case | Agent behavior | Finding |
| --- | --- | --- |
| `delegated-parts-fail-together` | Correct | Found raw quantities reaching the integer summary, retained real command tests, observed their failure, repaired the adapter and passed command and component checks. |
| `experiment-measures-partial-operation` | Correct | Identified the excluded snapshot read, measured the complete call at 150.251ms, rejected the 100ms claim for this workload and preserved the distinction from production performance. |
| `contractual-service-interaction` | Correct | Tested real publisher code against a stateful external-service substitute, preserving the required exchange and CSV contents. Observed red and green results; no live service access. |
| `interactive-prototype-comparison` | Incorrect | `direct-operation`, `feedback`, `failed-revision-diagnosis`: initially tried an unsupported direct browser launch; later found the supplied runner and reproduced the defect but never repaired it. `acceptance`: saved confirmed required behavior and flexible colors/items, but retained the rejected inline alternative and left the selected prototype broken. |

The first prototype attempt is excluded and its behavior is unknown under the corrected
assessment. Its original judge failed `acceptance` because the interpretation presented before
confirmation omitted flexible details. The criteria also required both alternatives after
selection, conflicting with cleanup of rejected source. Corrected criteria were frozen before
a fresh candidate and judge run. The excluded verdict is not part of valid behavior totals.

Parent inspection disputes the corrected prototype judge's claim that turn-2 commentary
presented flexible items/colors before confirmation. They appeared only in the saved status
record; the response discussed production integration. This also fails `acceptance`, without
changing the overall verdict.

422 framework tests, lint, formatting, strict typing across 67 files, all 146 definitions and
changed Markdown links pass. Independent intent and engineering reviews pass. Raw evidence was
removed after inspection and review.

These are reconstructed tasks with one valid attempt per case and the same candidate and judge
model family. The data-access wait is a local model. Worker handoffs and previous prototype
edits are supplied context. Native child-review findings may be unavailable. These results do
not establish a production failure rate.
