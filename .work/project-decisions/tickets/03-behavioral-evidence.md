# 03 Establish behavior across project and release decisions

**What to build:** Realistic evals and a blinded comparison that establish the integrated
planning behavior and preserve reasonable implementation autonomy.

**Blocked by:** [01 Project context](01-project-context.md); [02 Project planning](02-project-planning.md)

**Status:** complete

- [x] Ordinary project tasks cover new and existing repositories, undecided and already-approved
  platform work, development without a release plan, versioning and changed commitments.
- [x] Private criteria distinguish technical evidence from accepted product decisions and accept
  different sound implementations, document layouts and questions.
- [x] Fresh baseline evidence precedes the instruction change; comparisons hold candidate tasks,
  criteria, settings and tools fixed. Three final attempts cover every case and selected control.
- [x] Reports classify every attempt as correct, incorrect or unknown and report assessment
  completion separately, preserving earlier failures, exclusions and disputed judgments.
- [x] Existing relevant evals remain passing or receive evidence-based diagnosis; framework
  checks do not substitute for agent behavior evidence.
- [x] The final reviewed and tested source is applied unchanged, followed by affected checks.

## Accepted sources

[Testing decisions](../spec.md#testing-decisions) and
[eval authoring standards](../../../docs/eval-authoring.md).

## Completion evidence

A concise study links the tested diff and records all outcomes and limitations. Full outputs,
actions and available child findings are inspected and retained for required independent review.
